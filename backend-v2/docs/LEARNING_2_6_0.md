# v2.6.0：学习反馈与后续阶段

2026-09-06。继续迭代知时 v2；总体私人秘书目标仍在进行中。

## 用户能做什么

- 在「学习与研究」项目页记录收获、困难、难度感受及实际投入，可关联整个项目或某个任务。反馈为用户自述；保存反馈不会自动完成任务、改变任务预计分钟或推断掌握程度。
- 对知时说“例子能运行，但公式还不理解，请安排具体练习”，模型可记录原始反馈，再结合项目资料拟定补充内容。
- 点击一条反馈的「据此追加学习内容」，填写产出标准和投入并预览；也可直接「追加学习内容」规划下一阶段。沿用现有确认/自主权限落实。
- 新内容安排在已有未完成安排之后。前置任务没有可确定的结束时段时，新增内容保留待排；可先安排或完成前置任务，再重排。
- 原有任务、完成记录、人工安排及原文出处保留；新内容可引用经过校验的资料片段。规划窗口不够时明确显示未排入，需要调整窗口。
- 已落实方案记录其回应的反馈，在反馈下点击「查看回应方案」回看理由与产出。回应反馈不代表困难已经解决，后续效果可继续记录。
- 错误反馈可撤回；相关旧预览失效，已经落实的任务保留。反馈每页20条，支持继续读取历史。
- 持续跟进能发现尚无方案回应的偏难/偏易反馈；错过安排、日历冲突及窗口过期仍优先处理。同一情况复用跟进记录。

## 实现与接口

新增 `research_feedback` 表保存自述、关联项目任务记录、请求键、状态和时间；新增 `research_plan_feedback` 表关联方案及其反馈依据。采用新表，既有研究项目/任务/方案不需要增加列。启动时创建缺失表，真实旧版临时数据库升级已验证。

反馈保存与撤回通过项目版本写入声明；并发重放相同请求只保留一条，内容不同的同键请求返回409。反馈变更使项目版本递增，因此旧方案在落实前会拒绝。已应用方案重复执行只返回原结果。

方案新增 `extension` 类型，复用学习步骤拆分、日历空闲检测、每日容量、顺序约束、引用校验与事务落实。新增任务接入已有项目目标，并增加对应任务数关键结果目标值。新增和保留的任务均在预览中可核对。

| 接口 | 用途 |
| --- | --- |
| `GET /api/research/projects/{id}/feedback?before=...` | 活跃反馈分页 |
| `POST /api/research/projects/{id}/feedback` | 保存自述；包含项目version、request_key、note及可选字段 |
| `POST /api/research/projects/{id}/feedback/{fid}/withdraw` | 按项目版本撤回 |
| `POST /api/research/projects/{id}/extensions` | version、rationale、steps、feedback_ids，生成后续方案预览 |
| `GET /api/research/plans/{id}` | 回看回应方案及反馈编号 |
| `POST /api/research/plans/{id}/apply` | 按现有事务和权限流程落实 |

`GET /api/research/projects/{id}` 增加反馈首页。Agent 项目上下文中的反馈正文限制为每条600字符并明确标记摘录；完整反馈通过分页工具读取。任务关联编号为 `tasks[].id`，不是实际 `task_id`，工具描述与界面选择由程序说明。

新增工具：`record_research_feedback`、`list_research_feedback`、`withdraw_research_feedback`、`preview_research_extension`。记录与预览为 safe，读取为 readonly，撤回为 confirm；实际新增任务继续由 `apply_research_plan` 的统一权限门处理。内置学习技能区分用户反馈、真实完成进度和后续内容。

源码入口：`domain/research/feedback.py`、`domain/research/service.py`、`domain/followups.py`、研究路由与 Agent 工具。前端实际源码位于相邻 `frontend-v2/app/src/components/ResearchFeedback.vue`、`views/ResearchView.vue`、`api/research.ts`；REST 类型从后端契约生成。

## 当前边界与后续

本轮能够根据真实反馈追加巩固练习和后续阶段，尚不支持将新练习插入既有课程中间或按反馈替换已排内容。新内容也不会自动消除剩余课程量；先后关系与未排入项必须向用户说明。

后台反馈检查为规则驱动，尚未在无聊天回合时自动调用模型设计新的课程。它沿用学习跟进通知，让模型在用户对话及既有授权下继续处理。程序退出后不继续运行。

学习效果仍需用户反馈或可核对的练习产出，不能根据完成率宣称掌握。多材料摘要、材料质量筛选、真实模型评估、反馈驱动的内容替换，以及账本和其他个人事务的持续秘书能力继续推进。
