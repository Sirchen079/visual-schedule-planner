# v2.14.0 会话完整性修复与日历编辑

交付日期：2026-09-06。本次按用户要求排查窗口切换、长上下文与模型配置变化、取消/异常/重启三个方面，同时完成日历点击修改。完成后停止，不恢复长期自主迭代。

## 用户可见的变化

- 主窗口与悬浮窗各自保存当前会话、每个会话的文字草稿和附件选择；应用重启、后端端口变化后恢复。发送得到后端接受确认后才清除对应草稿。
- 打开同一个会话的两个窗口能同步已保存的运行进度；浏览其他会话时不再把原会话的运行状态、审批或计划套在当前会话上。
- 取消、供应商错误、超出上下文预算后保留已接受输入、已保存的部分回复和工具执行记录。重启后的未完成运行标记中断，不自动重做写操作。
- 会话记录可展开查看消息数量、工作上下文、模型容量与压缩摘要。模型可通过仅限当前会话的 `read_conversation_history` 按关键词、消息和偏移回查原始记录。
- 日历的日/周行程块、月视图行程名称可点击编辑名称、日期、时间、地点、类别和备注。保存后刷新日历；保存错误保留输入。重复行程显示系列范围，保留原 RRULE；当前修改应用于整个系列。
- 带提醒的行程改为全天时，可填写全天提醒时间，原提醒偏移保留；原有提醒设置入口继续可用。

## 排查结论与修复依据

| 已复现的问题 | 影响 | 最终处理 |
| --- | --- | --- |
| 仅在模型正常结束后写入完整消息 | 取消或模型报错后，已显示输入、回复和已执行工具从下一轮历史消失 | 接受时先写输入与回复占位；流中和每个执行节点保存检查点，工具结果单独持久化 |
| 新会话在执行内部才取得编号，首轮运行未按真实编号锁定 | 两个窗口可能在同一个首轮会话重叠执行 | 运行开始前创建会话并登记编号；运行结束且已启动工具收尾后释放占用 |
| 取消立即解除运行占用，线程中的写工具仍在执行 | 新轮次或删除可能与上一轮尚未结束的写操作冲突 | 等待已启动工具返回、保存执行凭据；此间继续拒绝并发发送和删除 |
| 历史加载硬保留 12 轮，压缩失败后仍裁剪；摘要输入只取每条前段 | 长对话早期约束或长消息中后段消失 | 取消强制按轮裁剪；分块覆盖全部摘要文本；摘要失败保留原历史；请求预算不足时明确停止，不静默裁剪 |
| 历史请求中的重复 instructions 被逐轮计入容量 | 128k 等大窗口也可能过早压缩 | 按已安装 PydanticAI 的实际准备语义，只计当前生效的 instructions；保留消息内容 |
| 切换会话先清空列表，草稿发送前清除，刷新无会话选择恢复 | 网络失败、重载或切窗口表现为上下文清空 | 历史成功加载后再切换；每会话草稿；主窗/悬浮窗独立持久工作区和修订检查 |
| 审批、计划等异步完成后使用了当前全局会话 | 迟到结果可能污染新会话或恢复错误会话 | 捕获会话/运行/操作身份并检查后续结果；服务端同时验证会话归属与运行状态 |

业务数据（如日程、账单）是私人秘书的共享本地资料，不属于跨会话泄漏的聊天记录。对话原文、工具回执和审批的读取与恢复按会话编号隔离。

## 参考 pi 与 Claude Code 的取舍

pi 的会话记录保留有身份和父关系的条目，并从会话路径构建模型上下文；压缩记录与原始条目分开保留。这支持本次采用“持久原始记录 + 工作上下文 + 压缩归档”的分层，但本应用仍使用 SQLite，没有照搬 pi 的 JSONL 分支树。参考 [pi session format](https://pi.dev/docs/latest/session-format)、[pi compaction](https://pi.dev/docs/latest/compaction) 和 [session-manager 源码](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/src/core/session-manager.ts)。

Claude Code 的公开文档说明会话恢复、fork、压缩与上下文查看，并提示同一会话在多个终端并用的影响。这里借鉴显式会话身份、恢复和可观察上下文；对同一会话选择串行执行，并同步两个窗口的持久进度。该比较依据公开文档，没有把 Claude Code 的内部实现当作已知事实。参考 [Claude Code sessions](https://code.claude.com/docs/en/sessions) 和 [How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works)。

## 实现与兼容性

新增 `AIWorkspace`、`AIContextCheckpoint`、`AIToolExecution` 表；旧消息及业务表保留，启动时建缺失表。工作区以 main/widget 区分；写入带 revision，前端串行保存并处理冲突。新端点见 `docs/contracts/openapi.json` 与前端生成契约。

`session_store.py` 保存接受记录、执行检查点、工具回执与压缩前完整历史。运行中的流快照约每秒落盘，节点结束也保存。应用退出先请求取消、等待任务收尾再释放数据库。进程硬终止后恢复最近已落盘检查点；无法确认的工具结果明确标注，不当作成功或自动重放。

摘要采用全量文本的有限分块合并，并在统一截止时间内执行。空结果、超预算或超时不替换旧历史。运行时完整请求仍检查所选模型的上下文与输出预算；换用更小容量模型时，可能需要成功压缩或明确停止。不会因换模型而重置会话身份。
