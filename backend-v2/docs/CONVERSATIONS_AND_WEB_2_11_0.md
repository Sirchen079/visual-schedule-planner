# v2.11.0 新对话隔离与网页长资料

## 新对话修复

用户报告点“新建会话”后仍带着旧聊天上下文。已定位并修复：`startNew` 调用的 `run.reset()` 保留旧 `conversationId`；发送时 `opts.conversationId ?? keepConversation` 又把明确代表新会话的 `null` 替换回旧编号。后端收到旧编号后会加载旧会话历史，因此也会实际影响模型请求。

新建现在同时清空当前会话指针、运行内容、聊天显示、输入草稿、计划模式和待发送附件。发送严格区分显式 `null` 与省略参数；首次 `run_started` 返回的真实会话编号接回当前视图，之后正常续聊使用该编号。旧会话保留在会话列表中，重新选择可查看原来的记录。

切换会话立即清除上一视图的消息；不同会话的实时输出和审批卡不混在一起。历史加载和附件上传使用视图版本检查，迟到响应不会污染新对话，包括切走后又切回同一编号。建立流连接期间也会锁住重复发送和新建；取消仍保留取消状态。上一轮已完成内容在下一次发送前从服务端读取，正常续聊保留本会话前几轮的显示。

新对话隔离的是聊天消息。当前日程等应用状态仍由秘书的既有上下文规则提供；学习页面的项目背景仍由“结合当前项目”复选框控制。

主要前端文件：`stores/run.ts`、`stores/conversation.ts`、`components/chat/ChatInput.vue`、`ChatThread.vue`、`timeline.ts`。主窗口和悬浮窗使用同一修复，不改后端消息读取协议。

## 网页资料

此前研究项目只保存网页前 8,000 个字符，长教程后段无法再读。本版将网页正文存为资料库快照并立即分段索引。项目与聊天仍返回短预览，`read_material` / `search_materials` 可定位、阅读后续段落，学习任务可引用经过原文核验的 `source_refs`。

“学习与研究 → 项目资料”新增“重新获取网页”，显示获取时间和历史版本。旧版截短缓存可重新获取；内容变化时创建新的资料编号和正文快照，原任务、计划及其引用保留原版本。内容相同的刷新复用现有编号；并发刷新只创建一个新版本。失败时保留已有正文并显示失败原因，重试可恢复。已删除的相同快照不会被静默恢复。

网页读取继续遵守设置中的内置、Tavily 或 MCP 服务选择。内置读取逐跳检查公开地址，最多下载 2MB 并保存 500,000 字符；超过容量时标明未读取范围。第三方服务返回的正文保留来源与完整性不确定提示。只保存本次得到的文本，不自动读取动态加载、登录后内容或页面链接；二进制链接会提示上传文件。独立 `web_fetch` 仍为 8,000 字符的只读预览，研究项目使用完整快照路径。

新增 `research_sources.superseded_by` 的幂等补列；新来源占用原 URL 的当前版本键，历史来源保留原编号。正文采用内容与 URL 共同寻址的资料库记录，不覆盖旧快照或用户笔记。`POST /api/research/projects/{id}/sources` 支持 `refresh`；单来源 `/fetch?refresh=true` 与 Agent 的 `add_research_source(refresh=true)` 同步接通。
