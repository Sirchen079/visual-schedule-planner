## 使用

把文件、图片交给主对话并说“帮我整理”，普通材料整理为待办、日程或收支候选；课表继续使用专门导入流程。仅要求阅读或总结时不应创建候选。左侧「收件箱」查看待确认、已落实、已忽略记录；无 AI 配置时也可手动粘贴材料、填写候选。

每条候选保留原文与来源名称。可核对、调整类型及字段、记录疑问；有未解疑问时禁止落实。修订被忽略条目会重新进入待确认。确认后创建真实任务/日程/账目，已落实记录保留来源和目标状态，目标后来被删除也不会因重试复活。

Agent 的修改/确认/忽略工具沿用现有权限门和自主程度，标准档需确认，自主档或已有授权按原规则执行。界面按钮代表用户直接执行。候选创建本身是 safe 写入，谨慎档也要批准。

## 面向探索能力较弱模型的链路

1. 附件解析和原图由运行时准备。模型直接获得 source_file_id、正文/视觉输入、既有处理记录与总数，无需先猜编号或重复找文件；记录未展示完时指向分页工具。
2. 普通材料明确指向 propose_inbox_items；公共字段、三种类型的最少字段和稳定位置键有说明。金额/日期不明时澄清；参数校验不会代填不明事实。
3. 创建候选返回结构化 items 和 next_step，明确候选尚未实际执行。应用/忽略过的原文事项不可换工具重建。
4. 并发或重复提取冲突返回 code、next_call.tool、next_call.args 和下一步说明，可直接读取指定候选；数据版本阻止陈旧写入。
5. 程序生成文字材料 capture_key，审批暂停后从已保存用户消息恢复，模型不需要生成或记住幂等上下文。
6. 工具异常与参数重试在 SSE 中标为 ok=false，修正后可继续；不会把错误结果显示成工具成功。

这些措施降低工具探索与记忆负担，不构成对所有较弱模型的成功率承诺。当前未自动收窄整套工具清单，也未针对特定后训练模型做真实供应商评估。

## 数据与一致性

- `inbox_items` 保存来源指纹/原文位置、候选JSON、疑问、状态、版本、目标ID与时间。
- 上传仍产生独立资料记录和物理文件，避免其中一个删除影响另一个。相同文件字节的 SHA256 加稳定 item_key 构成候选唯一键，改文件名重传也可找到之前处理记录。
- 旧 v2 的 library_files 增加可空 content_sha256 字段；旧附件首次读取时补算摘要，既有解析缓存保留。启动迁移测试覆盖真实旧表缺列状态。
- 批次候选要么全部提交，要么全部回滚。落实的版本领取与目标创建共享数据库事务，目标创建失败会回滚领取与目标；并发点击、重复请求返回已创建目标。
- task/event/ledger 的原服务默认提交行为保持；仅收件箱在外层事务中使用 commit=False。
- REST：`GET/POST /api/inbox`，`GET/PUT /api/inbox/{id}`，`POST /api/inbox/{id}/apply`、`/reject`。列表按状态、来源和分页筛选；OpenAPI与前端类型同步，SSE字段结构未增加。
