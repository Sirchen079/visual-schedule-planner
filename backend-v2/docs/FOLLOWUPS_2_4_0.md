# 知时 v2.4.0：持续跟进学习与研究

日期：2026-09-06。本批只迭代 v2，完整私人秘书目标继续进行中。

## 使用与行为

学习项目现在有「知时在跟进」面板。程序运行期间，后台启动时及每轮结束5分钟后检查实际任务、日历冲突和规划期限，无需打开项目页面或调用模型。

- 错过原时段、尚未排期或出现新冲突：准备重排预览，通过通知进入具体项目和跟进记录。默认由用户确认后落实。
- 阶段任务全部完成：提示回顾成果；规划窗口结束但仍有未完成任务：请用户补充时间，不偷偷延长明确期限；项目创建满24小时且已到开始日期但尚无任务：提示落实计划。
- 同一情况复用记录，不按轮询次数重复通知。「两小时后提醒」「明早提醒」持久保存；「忽略这条」抑制同一情况，新问题仍会产生跟进。归档项目停止监测并收束旧待处理记录。
- 「持续跟进全部学习项目」是全局开关，可随时暂停。暂停后仍可手动检查、生成建议和手动确认。
- 同时启用现有秘书自动档、持续跟进，且现有权限允许 `apply_research_plan` 时，完整可行且覆盖全部问题任务的方案才自动落实。未排入项目、保留的人工冲突留给用户处理。实际写入前再次检查开关和权限。
- 重排复用真实任务，保留完成记录、正在进行任务、用户修改的未来安排和已删除事项。后台调整有单次通知回执；重复落实只读既有结果。

## 一致性与恢复

新增 `secretary_followups` 表，以问题证据指纹防重复，状态、版本、方案、通知及稍后提醒时间入库。证据包括错过的具体时段编号，使同一任务第二次错过新时段时仍能提醒。

跟进写入领取和研究计划落库处于同一事务，版本冲突或日历变化拒绝旧建议。模拟并发检查、稍后提醒抢先、写入前撤销权限、日历事务完成后进程中断，均有针对性测试。中断后的后台检查恢复回执，不再次创建任务。部分落实后若原因仍存在，记录保持待补充；日历可用容量变化后可重新准备建议。

通知表幂等补充 `target_path`，旧提醒保留。前端只接受固定格式的内部项目/跟进链接。面板读请求防止旧响应覆盖新选择，收起详情后后台刷新不会强行重开。界面显示全局开关与实际自主程度说明。

调度器改为每个定期任务独立运行，慢模型请求不会阻塞提醒或跟进；同一任务正常运行期间不重叠。普通每日自动档排程和拆解排除学习项目任务，以免绕过项目的先后关系与时间预算。

## Agent 流程

`check_research_progress` → `get_secretary_followup`（需要查看或冲突恢复时）→ `apply_secretary_followup`。工具直接给出实际编号、版本和确定的下一调用，预览只返回有上限的安排摘要。错误版本返回 `followup_conflict` 和准确的读取参数；再次落实已完成方案只返回原结果。

需要补充时间或阶段已完成时，工具返回完整项目约束及明确的停止/补充条件，不把模型引回反复读取同一项目的循环。稍后提醒和忽略使用 `respond_secretary_followup`，沿用已有权限门。

API：`/api/followups`、`/status`、`/preferences`、`/check`、`/{id}`、`/{id}/apply`、`/{id}/respond`。OpenAPI 与前端类型已同步。

## 边界与后续

本批新增跟进只覆盖学习/研究项目。退出知时后不会继续检查，重启会读取持久状态；它不是操作系统独立后台服务。没有新增周期性模型推理或无人值守研究抓取。用户反馈驱动的课程内容调整、测验、下一阶段自动扩充、长材料完整分段阅读和真实供应商模型质量评估仍待完成。

独立调度解决慢任务阻塞，不代表能强制终止已进入线程的同步模型调用。退出时取消异步等待仍不保证后台线程内已开始的工作立即停止，此项需继续增强可恢复取消机制。

安装包使用本机 Electron33.4.11 生成，验证对应 `win-unpacked`，本批未执行 NSIS 安装/卸载，也未用真实用户数据做升级实验。先前版本发行物保留。
