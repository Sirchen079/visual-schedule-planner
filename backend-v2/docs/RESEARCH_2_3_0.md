## 使用

在「学习与研究」建立项目，写下主题、希望掌握的内容或产出、已有基础、期限和可用时间。也可直接告诉左侧知时你的想法，由 Agent 建立项目并继续检索、关联资料和拟定计划。打开项目时，对话输入框显示可取消的「结合当前项目」，模型获得该项目最新状态；离开页面后停止附带此上下文。

- 资料：按主题检索公开网页，逐条获取正文并保存到资料库；也可输入公开链接、上传本地材料或关联资料库已有文件。部分失败时保留成功结果并显示每条失败原因。相同文件字节复用项目资料引用。
- 规划：Agent 提供按顺序的学习内容、完成标准、估计投入及真实资料编号，程序拆成时段并按日历空闲安排。无 AI 配置时可手动填写学习步骤。
- 落实：预览时不创建真实任务。点击落实或经 Agent 权限门批准后，目标、任务、资料关联及日历在同一事务中创建；重复点击或模型重复调用返回原结果。
- 进度：在项目内标记完成，或在看板修改任务，项目随实际记录更新。修改可用时间后可预览重排，已有任务编号保持；已完成、正在进行、手动修改的未来安排与已删除任务保留现状。
- 窗口不足：明确列出未排入项及原因，落实后仍保存为待办。没有截止日时先规划两周，没有基础或可用时段时明确列出假设。
- 归档：保留项目资料、实际任务和日历，可恢复继续使用。

## 程序组织的 Agent 流程

`create_research_project` → `research_project_sources` 或 `attach_research_material` → `preview_research_plan` → `apply_research_plan`。已有项目先 `get_research_project`，时间调整使用 `update_research_project` → `preview_research_replan` → `apply_research_plan`。

资料搜索、正文获取和资料库写入由一个工具组织，逐来源报告结果。模型不需要猜任务编号、生成具体时间或逐条创建任务。错误资料编号、陈旧项目版本、日历变化返回 `research_conflict` 与可直接调用的 `get_research_project` 参数。读取项目按每页3份正文、20项任务返回，附明确的继续读取工具；聊天自动上下文仅注入正文摘要。已落实计划的重复调用只读原结果，不再次触发审批。

新表：`research_projects`、`research_sources`、`research_plans`、`research_tasks`。项目内容版本、日历指纹和事务内写入领取阻止陈旧预览落实；日历指纹涵盖实际事件、任务排期、每日容量、工作时段与项目任务状态。重排只删除能与程序保存记录逐字段对应的未来排期，保留人工调整。程序排程修复了工作时段之外的事件吞掉空闲、重复安排已排任务、忽略已用容量和大任务阻塞小任务空档的问题。

REST：`/api/research/projects` 及单项目的资料、材料、计划预览、重排、归档接口；`/api/research/plans/{id}/apply` 落实。聊天增加可选 `research_project_id`，OpenAPI 与前端类型同步。

## 当前边界与下一步

“已获取正文”仅说明抓取成功；内容准确性、来源适合程度与学习步骤质量仍需要模型及用户核对。正文最多8000字符，较长资料尚未完整分段阅读。图片可通过对话视觉输入理解，但关联研究材料尚要求可解析文本，不把无正文图片声称为已读资料。

本批提供按进度和新约束重新安排时间的闭环，尚未实现无人值守的周期研究、自动扩充下一阶段课程、依据测验表现调整教学内容或自动随进度触发重排。冻结 Agent 验收使用回环假模型验证工具协议与状态，不等同于对真实供应商或较弱模型的内容质量评估。

后续优先：长期秘书的可恢复执行记录、主动检查与通知、错过任务及约束变化后的建议；长材料处理、真实视觉/文本模型场景评估；预算、转账和账单导入。完整目标未完成。
