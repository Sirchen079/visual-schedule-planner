# v2.10.0 独立日程提醒与通用日历

固定会议、课程、出行和全天事项现在可在日程本身设置提醒。聊天或材料整理中的提醒要求会进入日程候选，确认后只创建一条带提醒的日程，无需额外建一个同名待办。

## 使用入口

- 日历中打开一项日程，在详情底部选择提前时间并保存。支持准时、提前 5 / 15 / 30 分钟、1 小时、1 天和自定义分钟；最多 8 个时间点，最远提前 7 天。关闭提醒不会删除日程。
- 全天事项需要填写当天的提醒时刻，不会默认在午夜打扰。固定时间日程按开始时刻计算提前量。
- 材料收件箱中，日程候选可核对提醒设置，列表摘要显示提醒信息。确认后可直接打开对应日期的日程详情。
- 通知显示“查看日程”，点击后进入该次发生日期并打开详情，同时标为已读。重复日程的详情显示所选日期，另行保留首次日期与重复规则。

提醒按本机日期时间运行。应用开启时周期扫描，睡眠或重启最多补查最近 7 天；同一重复日程较早的漏过提醒收敛为最近一条，避免积压通知连续弹出。后台关闭后不会继续执行，重新打开后才补查。桌面通知开关仍在设置中管理，应用内通知保留。

## 重复与修改

支持按天、周、月、年重复的单条 RRULE，包括单双周等规则。当前不支持日内多次或复合 RRULE 的事件提醒，保存时会说明原因；无提醒的旧日程不被强制改写规则。全天提醒时间、提前量和日程改期均可编辑；提醒编辑作用于整个重复系列，界面和 Agent 工具均明确提示。

改期后按新的实际发生时刻计算提醒，关闭或删除后不再生成后续提醒。已送达记录保留为历史，不撤销已经弹出的通知。通知幂等键同时包含日程身份、该次发生时刻与提醒时刻，重启和重复扫描不重复生成，删除后复用数字编号也不会误用旧记录。

## 日历修复

旧日历把所有事件都当作有完整起止时间的课程，全天事项可能触发空时间排序错误，早晚事项可能被时间轴裁剪。本批按真实可空时间处理排序与展示：日/周视图保留白天时间轴，并在“全天与其他时段”列出全天、时间未定以及超出时间轴的安排；所有条目都能打开详情。不会给未知结束时间补造时长。相关文案从“课表/节课”改为“日程/项”。

## 兼容与验证

旧数据库幂等补列，旧日程默认关闭提醒。旧收件箱候选按当前字段默认值规范化比较，新增提醒字段不会造成重复整理时的假冲突。事件落实与来源关联仍在同一事务；新通知与持久扫描游标一起提交。

新增工具 `get_event` 提供完整时间与提醒设置；`create_event` / `update_event` 可设置提前分钟和全天提醒时刻。修改保留原有确认权限，读取工具可用于计划模式与只读子代理。用户只要求阅读材料时不会因此创建日程。
