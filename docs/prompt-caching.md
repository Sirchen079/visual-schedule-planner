# 提示缓存与输入消费

提示缓存由模型服务商执行。知时负责保持可复用的请求前缀、发送相应接口支持的缓存参数，并展示回传用量；不会在本机假造缓存命中，也不会为了维持缓存定时调用模型。

## 请求如何保持稳定

- 固定系统规则保持不变。实时本机时间放到消息末尾，每次请求刷新，但不改写历史消息中的时间。相对日期仍以用户原消息日期为准。
- 内置技能按需追加到消息历史；相同版本已在当前上下文中时不重复追加。压缩后缺失且仍需要的规则会在请求发出前重新补齐。外部工具可用状态也只在变化时追加。
- 工具定义按名称排序，参数 schema 的对象键保持确定顺序。按需发现和权限检查仍然生效，没有把所有工具、全部技能一次装进每条请求。
- 长工具结果保留完整原文，并用可分页读取的引用控制输入量。真正接近上下文预算时仍允许压缩；不会为了保住缓存而让请求超限。
- 程序补充的时钟和技能有本地类型标记，不会被计作新用户轮次，也不会在压缩时取代需要保留的用户原话。

当任务确实需要加载新工具、用户更换模型或技能、或历史被压缩时，前缀仍可能变化。稳定序列化避免无意义的变化，不能消除必要变化。

## 各接口的处理

| 接口与选项 | 知时发送什么 | 使用条件 |
| --- | --- | --- |
| 原生 Anthropic，按接口默认 | 工具、系统规则、消息边界的 `cache_control` | 接口支持提示缓存；默认 5 分钟，可选择 1 小时 |
| Chat Completions / Responses，按接口默认 | 保持稳定历史，使用服务商自动缓存；OpenAI 官方地址额外发送稳定会话缓存键 | 自定义中转地址不自动假定支持额外缓存参数 |
| 会话缓存键：发送 | 同一配置、同一会话使用相同的非明文标识；新执行轮次不更换键 | 服务商支持 `prompt_cache_key`；这只是路由提示 |
| Anthropic 中转缓存标记 | 在 Chat Completions 的系统与消息内容块附加 `cache_control` | 由用户明确选择，服务商必须支持这种转换格式 |
| 不发送缓存参数 | 不发送上述显式参数，并移除历史中遗留的缓存断点 | 用于排查不接受额外参数的服务；不能关闭服务端自己的自动缓存 |

中转模式不会根据模型名字自动开启，也不会自动切换接口。它保留最近两个消息缓存边界与系统边界，实时钟在新边界之后。原生 Anthropic 保留的消息断点由适配器限制在接口允许的数量内。改变保留时间会同步更新历史断点，避免混用不符合接口顺序要求的保留时间。

1 小时缓存可能有更高写入价格，不等于一定更省钱。默认不延长，也不进行付费预热。具体最短输入长度、时效、路由和价格由模型及服务商决定。[Anthropic 官方说明](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)

## 怎样核对是否有效

对话状态栏显示输入总量、输出、缓存读取量、读取占比及已报告的缓存写入量。缓存读写属于输入总量的一部分，不能重复相加。输入总量仍用于上下文预算，不能扣掉缓存读取后判断是否需要压缩。

建议在同一会话、同一模型设置下继续正常对话，比较第二次及后续请求在服务商账单中的新输入、缓存写入和缓存读取。第一轮冷启动、短于模型缓存门槛、过期、更换工具集或服务端换路由，都可能不命中。不要为了测试反复发送长材料或无意义请求。

- Chat Completions 读取 `usage.prompt_tokens_details.cached_tokens`。
- Responses 读取 `usage.input_tokens_details.cached_tokens`。
- Anthropic 读取 `usage.cache_read_input_tokens` 与 `cache_creation_input_tokens`；适配器统一计算包含缓存部分的输入总量。

知时保存统一的 `cache_read_tokens`、`cache_write_tokens` 到执行记录，并通过事件回传。旧记录或未返回统计的接口无法补算，显示 0 也可能是未报告。这里的读取占比不是费用折扣。最终费用应核对服务商账单。[OpenAI 官方说明](https://developers.openai.com/api/docs/guides/prompt-caching)、[Anthropic 用量说明](https://platform.claude.com/docs/en/build-with-claude/prompt-caching#tracking-cache-performance)
