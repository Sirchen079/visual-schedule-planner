# AI 接入教程

[返回首页](../README.md)

## 接入 AI 前要准备什么

配置模型后，就能在对话区让 AI 整理材料、创建任务和安排日程。准备好服务商提供的密钥、基础地址、模型名称和接口格式，按下面的步骤填写即可。

知时通过你的模型服务账户调用 AI，费用由服务商结算。教程可以离线阅读，调用在线模型时需要联网。

## 还没有账号或密钥，怎么办

1. 打开你选择的模型服务商的官方开放平台，按其说明注册、登录。
2. 找到“API”“开发者”或“密钥管理”，创建 API Key。API Key 是平台单独生成的密钥，API 额度和计费方式可在控制台查看。
3. 打开同一服务商的接入文档，找到下面四项。

| 要准备的资料 | 是什么 | 填写提示 |
| --- | --- | --- |
| API Key | 允许应用调用你账户额度的密钥，像密码一样保管 | 复制平台生成的密钥 |
| Base URL | 模型接口的基础地址 | 从接入文档复制基础地址 |
| 模型名称 | 模型的准确标识 | 按原样填写，或在知时中获取列表选择 |
| 接口格式 | 服务使用哪一种通信格式 | 按服务商文档对照下节选择 |

四项资料应来自同一服务商，申请时留意该平台的计费、模型权限和数据处理说明。

## 三种接口格式怎么选

在“接口格式”下拉框中，选择服务商文档明确支持的选项：

| 文档中写的格式 | 知时中选择 |
| --- | --- |
| Chat Completions / `/chat/completions` | OpenAI Chat Completions |
| Responses / `/responses` | OpenAI Responses |
| Anthropic Messages | Anthropic |

**Base URL 只填基础地址。** 例如 OpenAI 官方基础地址是 `https://api.openai.com/v1`，不要再加 `/chat/completions` 或 `/responses`。其他服务可能使用不同的域名和前缀，照其文档填写；也不要把完整的 `/messages` 请求地址填进基础地址框。

同一个模型在不同服务商处可能使用不同接口格式，按当前服务商的文档选择。联网、图片和外部工具在后文单独配置。接口定义可参考 [OpenAI API 文档](https://developers.openai.com/api/reference/overview) 和 [Chat Completions 与 Responses 的区别](https://developers.openai.com/api/docs/guides/migrate-to-responses)。

## 一步步配置

先打开 **设置 → AI 模型 → 添加配置**。在应用内阅读本教程时，也可以点弹窗底部的 **打开 AI 模型设置**。

1. **配置名称**：写一个自己容易认出的名字，例如“日常助手”。这个名字用于在配置列表中识别它。
2. **接口格式**：按上一节选择。
3. **Base URL**：粘贴服务商的基础地址。
4. **API Key**：粘贴密钥。先点服务商页面的“复制”，回到知时点击密钥输入框，再按 **Ctrl + V**。输入框会用圆点隐藏密钥。
5. **获取模型列表**：点一下，等待结果，再从“可用模型”中选择。如果不支持获取列表，可以在 **模型名称** 中手动填写服务商给出的准确标识。
6. **其他参数先保留默认值**，点击 **添加**。表单收起后，在配置列表找到刚添加的配置，再点击 **启用**。
7. 看到 **启用中** 后，回到对话区，输入“你好”，点输入框右侧向上箭头发送。出现正常回复，说明基本对话已接通。
8. 再发送“列出我的待办任务”。能读取任务后，再尝试创建或修改操作，检查实际保存结果。

填错了还没保存时，点击对应输入框，按 **Ctrl + A** 全选，再粘贴正确内容。等待结果时不要重复发送。

选好模型后，记得点“添加”和“启用”，再发送消息测试。调用权限可以在服务商控制台查看。

## 修改配置与扩展能力

编辑已有配置时，**Key 留空会保留原密钥**，填写新 Key 才会替换。更换接口格式或基础地址后，获取列表前需要填写对应服务的 Key。

基本对话成功后，再按服务商对模型的说明调整上下文窗口、最大输出、思考程度和输入能力。输入能力应与模型支持的格式一致，图片输入需要使用支持看图的模型。参数报错时可恢复默认值重试。

联网和视觉服务在 **联网与视觉** 中配置，MCP 服务在 **外部工具** 中配置。它们可能需要单独的密钥和权限。本地 stdio 类型会运行你填写的程序，只配置你了解并信任的服务。保存过的永久授权可在 **授权** 中查看和撤回。

## 缓存读取与消费怎么查看

对话状态栏的输入总量包含缓存部分。例如输入总量为 10,000 token，缓存读取为 8,000 token，剩余 2,000 token 为非缓存输入。各部分按服务商的价格计费，实际费用可在其用量明细中查看。

知时会保持固定提示词和历史前缀稳定，把实时信息放在末尾，按接口发送缓存参数。原生 Anthropic 默认启用缓存标记；OpenAI 兼容接口的自动缓存由服务商处理。缓存命中还取决于输入长度、模型、有效期及路由，第一条请求不一定有缓存读取。

在**设置 → AI 模型 → 添加配置或编辑 → 缓存与消费**中可以展开高级选项：

- **按接口默认**使用当前接口的默认缓存配置，首次配置可选此项。
- 服务商明确支持 Chat Completions 消息中的 `cache_control` 时，才选择**Anthropic 中转缓存标记**。
- 服务商明确支持 `prompt_cache_key` 时，可将**会话缓存键**选为“发送”。OpenAI 官方地址默认发送；其他地址需手动选择发送。
- 原生 Anthropic 或兼容中转可选 **5 分钟 / 1 小时**保留。1 小时通常有更高的写入价格，请按实际间隔和服务商价格选择。
- 如果服务商拒绝缓存参数，可选**不发送缓存参数**排查。它不会关闭服务商自己的自动缓存。

更新后，在同一会话、同一配置下继续正常对话，再到服务商用量明细比较后续请求。缓存读显示 0 也可能是接口未报告；以服务商明细为准。[OpenAI 缓存说明](https://developers.openai.com/api/docs/guides/prompt-caching)、[Anthropic 缓存说明](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)

如果缓存仍大幅波动，可在正常使用后打开**设置 → 诊断日志 → 导出诊断日志**，随问题反馈附上 ZIP。日志会记录请求结构是否变化和接口返回的缓存用量，帮助区分应用变化与服务商缓存策略。此功能也用于排查其他软件问题；日志自动脱敏，保存在本地，不会自动上传。

## 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| 提示未配置模型 | 是否点了“添加”，并在列表中启用？应看到“启用中”。 |
| 连接失败或超时 | 地址有无空格或填错？本机能否访问该服务？网络或防火墙是否阻止请求？ |
| 401 / 403 | Key 是否正确、失效或不属于该服务？账户是否有模型权限？ |
| 404 | Base URL、接口格式和模型名称是否匹配？是否把完整请求路径当成基础地址？ |
| 400 / 参数不支持 | 核对报错指向的参数、格式和模型能力，先恢复基础文字配置；若提示工具定义不兼容，更新知时后再试。 |
| 429 / 额度不足 | 到服务商控制台核对余额和调用限制；限流时稍后重试。 |
| 获取不到模型列表 | 先核对地址、Key 和网络；服务不支持列表时，按文档手填模型名称。 |
| 能聊天，不能完成操作 | 检查是否在等你回答问题或审批；也可能是模型不支持工具调用。 |
| 发图片或调思考程度后报错 | 核对服务是否支持相应输入和参数，关闭不支持的选项后测试。 |

仍有问题时，记录 **应用版本、接口格式、模型名称和去除敏感信息的错误提示**。不要公开 API Key、带密钥的地址、账单信息或聊天附件。
