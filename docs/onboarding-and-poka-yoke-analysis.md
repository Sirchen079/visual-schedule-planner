# 知时 · 防呆与新手引导优化分析报告

> 生成日期：2026-07-21。基于对 frontend/src、backend/app、desktop/electron 的全量代码走查。

## 一、总体结论

项目在「防呆」上已有不错的基础（软删除 + 回收站、统一 ConfirmDialog、AI 危险操作三段确认、乐观更新失败回滚），但存在 **几处高危的"失败静默"缺口**；在「新手引导」上则是 **完全空白** —— 没有首次启动检测、没有任何引导组件、没有示例数据，新用户首次打开面对的是一个空看板，而应用恰好有 10 个视图和大量隐藏效率功能（快捷键 1-9、Ctrl+K、Ctrl+Shift+A、自然语言创建）全靠用户自己发现。

好消息是：**实现首次引导的所有基础设施都已存在**——`app_settings` KV 表（天然标记位）、`EmptyState` 操作槽、provide/inject 全局服务模式、迁移场景的"首次弹窗"先例。做一个不依赖第三方库的引导流程成本很低。

## 二、防呆缺口清单（按优先级）

### P0 — 失败静默，用户误以为操作成功

1. **App.vue 顶层任务操作无 try/catch**（`App.vue:239-267`）
   `onSave` / `onQuickCreate` / `onStatusChange` 失败时是 unhandled rejection：弹窗不关、无提示，用户以为已保存。这是全项目最高危的防呆缺口。
   **建议**：补上 try/catch + error toast；`onSave` 失败时保持 TaskModal 打开。

2. **TaskModal 子任务与附件操作全部无错误反馈**（`TaskModal.vue:157-197`）
   `doAttach / doDetach / addSub / toggleSub / removeSub` 失败均无任何提示。
   **建议**：统一包一层带 toast 的错误处理（可抽一个 `withErrorToast(fn, 失败文案)` 工具函数全局复用）。

3. **SettingsPanel 多处保存失败静默回滚**（`SettingsPanel.vue:91,108,122,134`，代码注释自述"保存失败静默"）
   开关看似改了，实际没存上。
   **建议**：回滚的同时弹 error toast"保存失败，已恢复原设置"。

### P1 — 缺少确认/校验

4. **子任务删除无确认无撤销**（`TaskModal.vue:193-197`）——主任务删除有确认+undo，子任务却裸删。
5. **日历排期移除无确认**（`CalendarView.vue:555-568`）。
6. **AI 模型配置校验过弱**（`AssistantView.vue:97-100`）
   `canSaveConfig` 只查非空：URL 格式不校验、extra_headers / 联网参数 JSON 到提交时才报错且无字段级提示（`:201-219`）。
   **建议**：URL 格式即时校验（红字提示，复用 TaskForm 的内联校验模式）；JSON 字段失焦时预解析并标错。已有「测试连接」按钮，可在保存前主动建议"先测试连接"。
7. **后端 settings PUT 接受任意键值**（`schemas.py:379-382`）——键名拼错会静默写入脏数据。
   **建议**：加键白名单校验（以 `DEFAULTS` 的键为准）。

### P2 — 后端健壮性

8. **无全局异常处理**：422 校验错误返回 FastAPI 默认英文 detail 数组，业务错误是中文 `{"detail"}`，两种结构不一致；未捕获异常裸奔英文 500。
   **建议**：在 `main.py` 注册 `RequestValidationError` 和全局 Exception handler，统一为中文友好结构 `{detail: "...", fields: {...}}`，前端 toast 直接可读。
9. **iCal 导入无去重、无事件条数上限**（`routers/ical.py:42-46`，`skipped` 恒为 0）——重复导入即重复建任务；异常大文件可批量建上万任务。
   **建议**：按 (标题+起止时间) 去重并回报"跳过 N 项重复"；单文件事件数设上限（如 2000）。
10. **AI 502 错误拼底层异常原文**（超时/连接拒绝等英文）——新手看不懂。
    **建议**：`sanitize_provider_error` 之后再加一层"翻译"：timeout→"连接超时，请检查网络或代理"，ECONNREFUSED→"无法连接到该地址，请检查 URL"。
11. 上传无扩展名白名单（仅大小限制，`file_service.py:30-61`）——单机场景风险可控，优先级低。

### 桌面端（已有较好防呆，仅小改进）

- 后端拉起失败已有三层弹框保护 ✅，但文案技术化（`health timeout`），建议中文化并附"查看日志"入口。
- 端口占用自动顺延 ✅，但若 18731 上是旧实例残留进程，新实例静默换端口，建议检测到时提示"检测到旧版知时进程"。
- DDL 提醒依赖前端轮询，无系统通知回退——窗口异常时提醒静默丢失，可加 Electron `Notification` 兜底。
- `/shutdown` 无防护，本机任意进程可杀服务（`main.py:162-166`），可加一个启动时生成的随机 token 校验。

## 四、首次启动引导流程设计方案（可行性：高）

### 4.1 触发机制（后端，约 30 行改动）

- `app_settings` 的 `DEFAULTS` 增加 `onboarding_done = "0"`（`services/app_setting_service.py:9-29`，KV 表天然支持，零迁移成本）。
- 判定"首次"的推荐口径：`onboarding_done != "1"` 且任务数为 0（避免老用户升级后被强制引导打扰）。
- 可选：`GET /settings` 已有，前端启动时读取即可，无需新端点。

### 4.2 引导形态：三段式（全部用现有组件，不装第三方库）

**第一段：欢迎页（BaseModal + hero.png）**
首次启动弹出，3-4 屏轮播：
1. 欢迎使用知时 —— 一句话定位"本地优先的日程/任务/资料管理"，hero.png 终于派上用场
2. 核心三板斧 —— 看板管任务、日历看安排、总览看进展（配视图截图或 ArtIcon 图标）
3. 效率秘籍 —— `Ctrl+K` 命令面板、`?` 快捷键、`Ctrl+Shift+A` 全局快速捕获
4. AI 助手（可选）—— 一句话说明 + "去配置"跳转 / "稍后再说"
底部："跳过" / "下一步" / "开始使用"。完成后 PUT `onboarding_done=1`。

**第二段：空看板引导（EmptyState 操作槽）**
第一段结束后，看板整板空状态（当前缺口 #1）显示：
- 插画 + "从第一件事开始" + 主按钮「创建第一个任务」（打开 TaskModal）
- 次按钮「试试自然语言创建」并给出示例文案「明天下午3点写周报 #工作 !高」（点击直接填入快速创建框）
- 已有 `EmptyState.vue` 支持操作槽，改动小。

**第三段：渐进式提示（contextual tips，不做强制 walkthrough）**
不做 driver.js 式的全屏遮罩步骤引导（对桌面工具类应用侵入性强），改为"首次遇到某功能时给一次性提示"：
- 首次打开日历 → 轻提示"双击空白格可按日期快速创建，拖拽条目可改期"
- 首次打开时间轴 → "拖动条目整体平移，拖边缘调整起止"
- 首次打开助手且未配置模型 → 配置引导卡（见 4.3）
- 每条提示用独立 localStorage 键（沿用 `zs-*` 惯例）只出现一次，可统一在设置里"重置所有提示"。

### 4.3 顺手补的引导性防呆（与引导流程配套，收益大）

1. **AI 配置引导**：助手空对话状态（`AssistantChat.vue:74-77`）在未配置模型时显示"需要先配置模型才能对话"+「去配置」按钮（跳到 Settings 页签）；内嵌 AI 按钮的 tooltip 改为可点击跳转。发送前加配置预检，替代现在的"失败才报错"。
2. **快捷键帮助补全**：`shortcutGroups` 补齐日历/时间轴/日记视图内快捷键；在命令面板加"打开快捷键帮助"命令；首次引导第三屏已教 `?`，形成闭环。
3. **命令面板扩充**：补"新建习惯/新建目标/写日记"等创建动作。
4. **可选：示例数据**。在欢迎页提供"创建几个示例任务带我看看"选项（比强制种子数据更尊重用户）；后端加一个仅在 `onboarding_done != "1"` 且库为空时可调用的 seed 端点。

### 4.4 为什么不建议引入 driver.js / shepherd.js

项目 UI 组件已高度统一（BaseModal/EmptyState/ConfirmDialog + CSS 变量主题），自研轻量引导（欢迎弹窗 + 空状态 CTA + 一次性气泡提示）约 300-400 行代码即可覆盖，且天然适配深浅主题；第三方 tour 库的遮罩高亮在拖拽密集的看板/日历里容易定位错乱，还多一份依赖。
